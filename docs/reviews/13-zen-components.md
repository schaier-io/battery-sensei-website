# Zen component library review

## Scope and coverage

**Scope.** All 20 components in `src/components/zen/`, plus the two motion utilities
`src/lib/prefers-reduced-motion.ts` and `src/lib/use-count-up.ts`. Reviewed as a component
inventory, one pass per component.

**Stack.** TanStack Start + TanStack Router, React 19, Tailwind v4, `motion`, `lucide-react`,
`react-i18next`. Styling is Tailwind utilities plus CSS custom properties defined in
`src/styles.css` (`--sumi`, `--washi`, `--hinomaru`, `--kin`, `--line`, `--nezumi`).

**Convention documents found.** `CONTEXT.md` (ubiquitous language: Pro, Lifetime, Yearly
Patron, Guides, Feature pages, Saga; "Journal", "Battery Journal" and "battery history" are
retired), `PRODUCT.md` (brand register and accessibility bar), `src/styles.css` (token system
and all reduced-motion guards), `components.json` plus `src/components/ui/*` (shadcn-style
primitives). No Storybook, no interface ADR.

**Review boundary.** Read-only, source only. No browser was used, so anything needing a
rendered page is in **Not verified**. Consuming pages, `src/components/ui/*` and the
`styles.css` token values belong to other agents. `styles.css` was read as evidence of whether
a component's motion is actually guarded, not reviewed on its own terms. One consumer defect
is reported (`Health.tsx` tabpanels) because `Sparkline` forces it.

**Live versus dead.** Five components in scope render nowhere in the app. `ChargeChart`,
`ChargeRing`, `WarningOverlay`, `Enso` and `BrushTick` have no importer outside
`src/components/zen/`. `BrushRing` is imported only by `ChargeRing`, so it is dead too.
Severity below is ranked on real user reach, so defects confined to those files are
consolidated into one row (M2) whose fix is deletion.

## Verification

**Passed.**

- SVG audit. Read every `<svg>` in the 20 components. Decorative marks (`Enso:54`, `Hanko:39`, `BrushDivider:20`, `BrushRing:139`, `BrushTick:30`, `ChargeRing`'s four layers, `WarningOverlay:168`, `MenuBarMockup:141,279,313`, `RescueReceipt:58`, `SharedCardMock:107,140,160`) all carry `aria-hidden`. React renders the bare JSX attribute as `aria-hidden="true"`, which is correct.
- Focusable children in decorative SVG. `grep -rn "tabindex\|<a " src/components/zen/` returns no match. No decorative SVG contains a focusable descendant.
- Accessible names on interactive controls. The library has five: `VideoFacade.tsx:42` has `aria-label={title}`; `WarningOverlay.tsx:114,124` pass `label` into `StepButton`, which sets `aria-label`. The other two (`WarningOverlay.tsx:117,129`) have visible text. All five are named. Two of them are also inert, which is covered by M2.

- `will-change`. One occurrence in the components (`TiltCard.tsx:87`, reported as a finding). Every `styles.css` occurrence is limited to `transform`, `opacity` or `filter`. No `will-change: all`.
- Reduced-motion trace. Matched every animated class in the library against `src/styles.css`.
