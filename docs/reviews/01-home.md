# Home / landing page interface review

## Scope and coverage

**Scope.** The marketing home composition rendered by `/` and `/$lang`: `src/routes/index.tsx` →
`src/components/HomePage.tsx` → Hero, Categories, Features, Health, Compare, FAQ, Contact, plus the
zen components those sections render (`RotatingHeadline`, `Reveal`, `VideoFacade`, `TiltCard`,
`Sparkline`, `Enso`, `MenuBarMockup`, `Hanko`, `InkLevelBar`, `BrushDivider`).

**Excluded by the prompt.** `Nav`, `Footer`, `ThemeSwitcher`, `LanguageSwitcher`, `CurrencySwitcher`,
`Pricing.tsx`, `src/components/ui/*`, and the token definitions in `src/styles.css`. `styles.css` was
read as evidence for motion and color claims, not reviewed as a surface. `src/components/board/FeatureBoard`
(lazy-loaded behind the Contact "Roadmap" tab) was not inspected; it is a separate surface.
`api/contact.ts` was read only to establish what the Contact form accepts.

**Stack and conventions.** TanStack Start + TanStack Router, React 19, Tailwind v4 with
`@custom-variant dark (&:is(.dark *))`, radix-ui primitives via `src/components/ui/*`, `motion` for
spring physics, react-i18next with five locales (`en`, `de`, `es`, `fr`, `ja`). Color is a CSS custom
property system in `src/styles.css` (`--sumi`, `--washi`, `--hinomaru`, `--nezumi`, `--matcha`,
`--line`) with a full `.dark` override block at `src/styles.css:151`.

**Convention documents found.** `CONTEXT.md` (plan names, tier names, content-surface names, the Saga
rename), `PRODUCT.md` (brand register and an explicit accessibility bar at `PRODUCT.md:33`),
`docs/reviews/_BRIEF.md`. No `CONTRIBUTING.md`, `CODING_STANDARDS.md`, `AGENTS.md`, or design-system
doc. `PRODUCT.md:33` reads: "Use semantic controls, visible focus states, sufficient contrast in light
and dark themes, accessible names for icon controls, and reduced-motion fallbacks. Do not rely on
color alone to communicate comparison results or status." Several findings below are failures against
the project's own written bar, not an imported one.

**Boundary.** Source-only review. Per the brief, the browser and preview tools were not used, so every
claim that needs a rendered page sits in **Not verified**.

## Not blocking

Confirmed, real, and excluded by the finding cap:

1. `Compare.tsx:315-318`. The desktop info trigger is a `<span tabIndex={0} aria-label={...}>` with no `role`, and the `role="tooltip"` span at `:329` is not referenced by `aria-describedby`. It has an accessible name, so it works, but it is a control built from a `span`.
2. `Contact.tsx:256-283`, `:313-326`. `name`, `email` and `message` are `required` but carry no visible required marker, so sighted users learn which fields are mandatory only by failing. Separately, `:365` disables the submit button on `status === 'sent'` with no reset, so a visitor cannot send a second message without reloading.
3. `Compare.tsx:175` and `:293` use `transition-all`. Both animate exactly two properties (`color` and `transform`); name them.
4. Four separate inline copies of `window.matchMedia('(prefers-reduced-motion: reduce)')` in `Hero.tsx:120`, `Categories.tsx:37`, `RotatingHeadline.tsx:81` and `Sparkline.tsx:48`, while `src/lib/prefers-reduced-motion.ts` exists for this. None of the four listens for a `change` event, so toggling the OS setting does not take effect until reload. All four are otherwise correct: the rotation, the marquee, the chevron bob and the chart draw-in each skip cleanly.
5. `BrushDivider.tsx:22` hardcodes `<filter id="bd-rough">`, and `HomePage.tsx` renders the component five times, so the home page ships five elements sharing one DOM id and four of the five `filter="url(#bd-rough)"` references resolve to the first. `Enso.tsx:17`, `Sparkline.tsx:38` and `InkLevelBar.tsx:75` all use `useId()` for exactly this; copy that.
